# Expandable list regressions

`ExpandableList`, `TreeList` and `BusinessSortedTree` use the optional `ExpandableListAdapter` / `TreeListAdapter` constructors, with Chinese comments explaining component caching, stable keys and lifecycle ownership. `CallbackTree` demonstrates the function/callback constructor and directly implements `OnItemRender`, `OnItemRecycle` and `OnViewDestroyed`. Their scene suites exercise those public integrations. Runtime suites run the same projection, sorting, navigation, lifecycle, failure-recovery and warmed-allocation checks through both Adapter and function/callback constructors. Additional checks verify mutually exclusive rendering configuration, rejected estimates, shared Adapter instances with independent expansion/views, and cleanup isolation when one controller is disposed.

For the three-level callback scene, execute `ZRList.Tests.CallbackTreeSampleRegression.RunPlayMode` after importing the demos and `Tests~/SampleEditor`, without `-quit` or `-nographics`. It checks actual button events, 296-node virtualization, indentation, unread sorting, stable keys after rebinding, inactive bindings after recycling, descendant expansion retention, hidden-course navigation and cleanup. It also samples 1,000 warmed cross-range scroll updates with the real sample callbacks and verifies no new views or managed allocation events in that synchronous path; later Canvas rebuilds are outside the sampling interval. Success reports `CALLBACK_TREE_PLAYMODE_PASSED` and writes `Previews/CallbackTree.png`.

For callback consumers, configure the view factory and cleanup subscriptions before the renderer is initialized. `OnItemRender` may be subscribed after `Submit`; without a render subscriber, no blank items are created. While the list is enabled, adding/removing a render subscriber refreshes immediately, and removing the final subscriber recycles visible views while keeping the pool. Disabled lists defer this refresh/recycling until re-enabled. Navigation can temporarily bind off-screen rows for measurement, so render callbacks are not visibility or read notifications. `OnItemRecycle` ends the old binding, including refresh/rebind, and does not necessarily mean the view entered the pool. Dispose completes cleanup before releasing delegates, so do not unsubscribe cleanup handlers first.

The independent business sorting scene has a targeted Play Mode suite: run `ZRList.Tests.BusinessSortedTreeSampleRegression.RunPlayMode` after importing the demos and `Tests~/SampleEditor`, without `-quit` or `-nographics`. It exercises the actual controls and verifies notification/unlock/unread priorities, ID ties, independent flag mutation, ANY-descendant aggregation, sorting across four levels, retained physical views/anchors, task selection after rebinding, reset and virtualization. Success reports `BUSINESS_SORT_PLAYMODE_PASSED`; actual scene captures are saved to `Previews/BusinessSortedTree.png` and `Previews/BusinessSortedTree-Overview.png`.

The same `Tests~/Editor` import includes multi-level tree tests. Run `ZRList.Tests.TreeListRegression.Run` with the batch arguments below; success reports `TREE_REGRESSION_PASSED`. It covers a 10,000-level chain, deterministic random mutations, sibling sorting, hidden cycles/duplicates, subtree reparenting, expansion retention, both axes and size modes, anchor fallbacks, lifecycle recovery and six warmed allocation paths.

For the four-level `TreeList` scene, import the demo and `Tests~/SampleEditor`, then execute `ZRList.Tests.TreeListSampleRegression.RunPlayMode` without `-quit` or `-nographics`. Success reports `TREE_PLAYMODE_PASSED` and writes `Previews/TreeList.png`. It clicks all branch levels and a task, checks indentation and 462-node virtualization, tests business aggregation/sorting at every level, navigates to a hidden leaf, and runs the runtime suite in Play Mode.

Copy `Tests~/Editor` into an isolated Unity consumer project's `Assets/ExpandableTests` folder. The project must reference `com.zr.list` and `com.unity.ugui`. No NUnit or other test dependency is required.

Run the editor with:

```text
Unity.exe -batchmode -nographics -projectPath <consumer-project> -executeMethod ZRList.Tests.ExpandableListRegression.Run -logFile <log-path> -quit
```

Success reports `EXPANDABLE_REGRESSION_PASSED`. The suite checks snapshots and validation before commit, injected sorting and stable ties, retained expansion, dynamic sizes on both axes, old-snapshot unbinding, physical view reuse, stale binding rejection, cross-group moves, prefab replacement, anchor fallback, hidden-item navigation, disabled updates, error recovery, and warmed allocation paths. Allocation checks first verify that the GC.Alloc recorder observes an intentional allocation.

The fixture uses synthetic views to isolate controller/runtime allocation from application binding and Canvas rebuilds. Timings are diagnostic measurements, not hardware-independent performance promises. `Tests~` is not compiled or imported with the runtime package by default.

For the sample's Play Mode checks, also import **ZRList Demos** and copy `Tests~/SampleEditor` to `Assets/ExpandableSampleTests`. Run `ZRList.Tests.ExpandableListSampleRegression.RunPlayMode` with `-batchmode` and a log path, without `-quit` or `-nographics`. The runner exits the editor on completion and reports `EXPANDABLE_PLAYMODE_PASSED`. It checks actual button clicks, business-driven ordering, navigation, retained expansion and drag-origin compensation, then runs the runtime/allocation suite in Play Mode. It writes an expanded-scene screenshot under the consumer project's `Previews` directory.
